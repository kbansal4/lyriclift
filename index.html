Built as a graduate text analytics project, LyricLift combines VADER sentiment analysis with Word2Vec similarity. Its output gives songwriters four concrete starting points: danceability, loudness, acousticness, and energy.

01 / The problem

Lyrics arrive before the production plan.

A songwriter can know what they want to say and still be unsure how the track should feel. LyricLift uses patterns from successful songs to give that early creative decision some structure.

02 / Method

From a page of lyrics to a production brief.

The final Python implementation uses a compact four-step pipeline. Each step stays interpretable, so the recommendation can be explained rather than simply produced.

01

Clean the catalog

Keep songs released from 2000 to 2019, reset the index, and remove rows with missing or empty lyrics.

02

Read the mood

Use VADER compound scores to classify lyrics into five bands, from very negative to very positive.

03

Measure similarity

Tokenize lyrics, train 100-dimensional Word2Vec embeddings, then rank songs using cosine similarity.

04

Translate the result

Take the five closest songs with matching sentiment, average four production attributes, and explain each score in plain language.

03 / Model choice

Accuracy mattered. So did speed.

The team tested three approaches. The goal was not to choose the most complicated model. It was to find the best balance of semantic understanding, believable recommendations, and fast execution.

Final choice: Word2Vec paired a deeper reading of word relationships with the speed needed for an interactive recommendation tool.

04 / My contribution

The work behind the recommendation.

My part of the project focused on getting the data, sentiment logic, and model comparison into a dependable shape. That meant writing code, testing edge cases, and making the output useful to a songwriter.

Prepared the data

Filtered the catalog to a contemporary release window, removed missing records, and kept the inputs needed for lyrics, metadata, and production attributes.

Built the text pipeline

Tokenized lyrics with NLTK, implemented VADER sentiment analysis, and set the five classification bands used by the final model.

Tuned the thresholds

Tested lyrics across a range of known moods, then adjusted the compound-score cutoffs to reduce obvious sentiment misclassifications.

Benchmarked the models

Compared Word2Vec, BERT, and TF-IDF results by checking whether the recommended songs felt reasonable and whether the model could respond quickly.

Project takeaways.

01

Model choice is a product decision

BERT was powerful, but Word2Vec better matched the actual experience we wanted to deliver. The “best” model depends on the constraint that matters.

02

Interpretability changes the value of a score

A danceability value by itself is hard to use. Turning that number into guidance about rhythm, tempo, and instrumentation makes the output actionable.

03

Lyrics are full of context traps

Sarcasm, metaphor, conflicting emotions, and genre-specific language can all push a sentiment model toward the wrong reading.

04

Averages can hide useful differences

Two songs can share a sentiment and still sound completely different. A future version should segment by genre before averaging production attributes.

Potential next steps

  • Make recommendations genre-aware, especially for slang and different ways of expressing emotion.
  • Train embeddings on a dedicated music and lyrics corpus instead of learning only from the project dataset.
  • Use a larger catalog and validate results with structured feedback from songwriters and producers.
